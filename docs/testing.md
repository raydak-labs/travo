# Testing

Unit-green does not mean it works. Several real bugs shipped green because a fixture invented a field the device never emits.

## Layers

1. **Unit** with fixtures: verbatim captured device payloads, each with provenance (device, firmware version, date) in `testdata/`. Never hand-write a payload field.
2. **Container integration**: the official `openwrt/rootfs` image (25.12; 24.10 for the opkg adapter) with real `uci`, `ubus`, `rpcd`. Catches mocks that diverge from real semantics.
3. **Hardware playbook** per release on a real device. Some behaviour is provable only there: wireless apply/confirm, lockout, DNS composition with VPN + captive + AdGuard, sysupgrade survival, AdGuard reinstall, watchdog restore.

## Rules

- Mocks reproduce real semantics: `uci set` upserts (a mock that errors on an existing section is a false failure); a mock that ignores the device name is a false pass.
- A constant asserted against itself proves nothing. Check timing budgets against measured latency.
- Test the fail-closed direction explicitly: a broken AP reads DOWN; an unknown caller is refused.
- Property tests for the DNS layer stack (any push/pop order restores base).
- Transaction unit tests stub host-wide `sync` so disk load cannot consume the restore timeout; container and hardware tests use real `sync`.
- Table-driven tests for caller classification using real payload shapes.
- No destructive probes (e.g. reboot POST) against an unknown build: GET-only reachability first.
- Verify the running binary is the one under test (path + version) before measuring.

## Contract tests

Scripts parse; guard paths under `/etc/travo-greenfield-guards/`; every route is in the spec; auth covers every route (walk the live route table); strict-PUT coverage; spec field names match models; no feature writes UCI outside the transaction module; generated files (OpenAPI, TS client) have no diff.

## Mock mode

`--mock` runs the whole daemon against the mock `Device`, scripted from fixtures. Frontend development needs no device.

## Running the container layer

`mise run test:integration` cross-compiles the `integration`-tagged tests and runs them against real `uci`, `apk` (`openwrt/rootfs:aarch64_generic-25.12.6`) and `opkg` (`openwrt/rootfs:x86-64-24.10.8`, amd64: no arm64 24.10 manifest exists) (needs Docker). A second step boots the image with `/sbin/init` (procd as PID 1, real ubusd/rpcd/netifd) for tests that need procd. `mise run test:package` builds the release tarball and, in a booted `aarch64_generic-25.12.6` container, runs `install.sh` (refusals, install, health on `:80`, LuCI moved, other listeners intact), restarts the container (boot link), then `--uninstall` and `--uninstall --purge`. It also runs the signature cases (ADR 0007) with throwaway minisign keys from the host (`minisign` from `mise.toml`): no `.sig` refuses (`--insecure` hint); `--insecure` installs and writes no key; a valid `.sig` installs and stores the tarball key; a tarball with another key refuses ("differs from the installed key") and installs with `--rotate-key`; a `.sig` from another key and a tampered `checksums.txt` both refuse with "signature check failed". The real release key is never used. `mise run test:port80` checks the dual-stack port swap, exact LuCI listener restoration, rollback and retry after interruption, and refusal when another process owns port 80. Both packaging suites run on arm64 and are outside `mise run check`. CI runs it on every PR that touches non-docs files: one job per arch (`integration (arm64)` on the native arm runner, `integration (amd64)`), each running `mise run test:integration <arch>` (the arm64 job then runs `mise run test:package` and `mise run test:port80`); no arg runs both locally. Container fixtures prove format and quoting only, never wireless or netifd behaviour; mark them as such in `testdata/PROVENANCE.md`.

## Hardware layer

Test router: GL-AXT1800, OpenWrt 25.12.6, `ssh root@192.168.1.1` (key auth) when the operator has it on LAN. Start from a clean OpenWrt baseline for the release playbook. Before any live test, take a `sysupgrade -b` backup to the operator's machine and keep it outside the repo. Pause competing configuration writers and restore any paused processes afterwards. Diff `/etc/config/*` and the crontab against the backup after rollback tests. Never `wifi` / `wifi up/down/reload`. GET-only first.

`hardware`-tagged tests (`internal/txn/hardware_test.go`, `internal/dnslayer/hardware_test.go`, `internal/captive/hardware_test.go`) run ON the router from Ethernet: cross-compile with `GOOS=linux GOARCH=arm64 go test -tags hardware -c`, copy with `scp -O`, run with `-test.timeout` (no `timeout` in BusyBox). They change live wireless/DNS state and rely on the watchdog/stack to restore it; take a sysupgrade backup first and pause competing configuration writers. The reboot test needs a temporary boot hook that calls `Recover`; remove it after. Results of the first run: `testdata/device/axt1800-25.12.6/SPIKES.md`.

## Hardware playbook (run before each release; console or Ethernet fallback ready)

Done on 2026-11-09 (results: `testdata/device/axt1800-25.12.6/SPIKES.md`): payload captures; watchdog restore without confirm, after daemon kill and across reboot; wrong uplink password reads `carrier:false` and rolls back; DNS layer round trip with AdGuard and captive.

Per release, each from Ethernet unless stated (issues with label `needs-hardware` add their step here when they merge):
1. On clean OpenWrt, verify LuCI login on port 80 and record the uhttpd listener values. Install the release tarball without `--port`. Set up and log in to greenfield at `http://192.168.1.1/` and verify LuCI login on port 8080. Check that `sysupgrade -l | grep travo-greenfield` lists the keep paths, including `uhttpd.orig`. Reboot and verify both UIs still answer. Run `--uninstall` and verify the original uhttpd listener values, their order and option/list form, and LuCI login on port 80.
2. Wireless change not confirmed: restores via `reload_config` alone; confirm keeps it.
3. From a phone on the AP, switch to client mode: refused with 409 `wifi_lockout_risk`.
4. Wrong uplink password: carrier stays false, rollback happens, UI says "rolled back" only after restore.
5. DNS: captive bypass over AdGuard restores base exactly; AdGuard stopped → fail-open within seconds.
6. Configuration backup (#64): sign in on the AXT1800, download the archive from System and verify it locally with `gzip -t travo-config.tar.gz` and `tar -tzf travo-config.tar.gz`. Confirm it contains router config entries. Keep the archive and its contents private.

7. Dashboard connectivity (#58): from Ethernet, verify the active interface and carrier against the kernel route and device status on a connected AXT1800. Verify the no-default-route state shows Offline and unknown uplink and carrier. Record each result without changing the router just to produce a fixture.
8. Reboot (#65): from Ethernet on the AXT1800 with a build that includes #65. GET-only first: `wget -qO- http://192.168.1.1/api/health` and record `boot_id` (B1) and `/proc/sys/kernel/random/boot_id` (K1). (a) With a wireless change applied but not confirmed, press System → Restart router → Restart: the UI shows "Confirm or roll back the pending change first." (409 `transaction_pending`), the router does not reboot, and `ls /etc/travo-greenfield-guards/` shows no `reboot-in-progress`. Roll the change back. (b) Press Restart router and confirm. The UI shows "Restarting…" within 1 s of the response, the Ethernet link drops, and within 3 minutes the UI reports "Router restarted" with a health `boot_id` different from B1. On the router: `uptime` is under 3 minutes, `/proc/sys/kernel/random/boot_id` differs from K1, `ls /etc/travo-greenfield-guards/` has no `reboot-in-progress`, `/etc/travo-greenfield/reboot.json` is absent, and `logread | grep -i 'stale guard'` shows no reboot entry. Sign in again; LuCI on :8080 and the daemon both answer. (c) Record pass or fail only, never the boot ids.

8. WireGuard tunnel status (#86): from Ethernet, configure `wg0` as in `testdata/device/axt1800-25.12.6/wireguard/PROVENANCE.md` and request `GET /api/v1/vpn/status` with a session cookie.
   - With `disabled=1`, expect `disabled`, or `configured` when a profile is selected.
   - With `disabled=0` and an unreachable endpoint, expect `no_handshake` with a null handshake age.
   - With a real endpoint after `ifup wg0`, expect `connected` with a handshake age under 180 seconds.
   Compare each result with `wg show wg0 latest-handshakes`. After disabling, run `ifup wwan` if the kernel default route is gone (device-facts §1).

**WiFi Join (#71).** Test over Ethernet with a backup and console ready. Join a known uplink with a band-compatible free radio. Record time to STA carrier and a kernel default route via the STA, then confirm and verify the route persists. Repeat without confirming and with a wrong password for the currently connected SSID. A stale carrier and route must not let the wrong password reach Pending (#115). Verify rollback restores the previous STA and route, and the UI reports rollback only after the transaction does. Verify the AP stays up and remains on a separate radio. Check mixed WPA2/WPA3 only with an operator-owned test network. Record the result in SPIKES.md with the SSID and BSSID redacted.

**Saved uplinks (#72).** Over Ethernet with a fresh backup. Save two visible uplinks from the WiFi scan and verify `uci show wireless` and the STA are unchanged after each save. Reorder them, reload the page and restart the daemon, and verify the order persists and `ls -l /etc/travo-greenfield/wifi-profiles.json` shows mode `-rw-------`. Select the second one and confirm it. Verify `connected_id` names it by comparing with `ubus call iwinfo info '{"device":"<sta ifname>"}'` (SSID and BSSID). Forget the connected profile and verify the STA keeps carrier and the kernel default route. If no second uplink is visible, or the two use different security (WPA2 and WPA2/WPA3), record that case separately. Record the results in SPIKES.md with SSIDs and BSSIDs redacted.

**WireGuard toggle (#87).** From Ethernet, take a fresh backup and load the operator's test profile. Enable through the VPN page and provide tunnel traffic if the peer is idle. Confirm after a new handshake. Disable and verify that wg0 is absent and that the kernel default uses the underlying uplink before confirming. Repeat enable with an unreachable controlled endpoint and verify rollback restores the original state, including the non-wg0 kernel default from a disabled baseline (#113). Use an unreachable documentation endpoint for the failed-enable case and verify the original uplink default is present when the watchdog reports RolledBack. Record the terminal states and elapsed times in SPIKES.md with credentials and endpoints omitted. Repeat one enable/confirm and one disable/confirm from the dashboard VPN card (#63).

**VPN zone on enable (#87 follow-up).** From Ethernet with the lock held, `uci export firewall` and `network` saved, kill switch OFF and no `travo_*` firewall sections. Enable the tunnel from the VPN page and confirm: `uci show firewall | grep travo` lists only `travo_vpn` and `travo_vpn_lan`, and a LAN client (`curl --interface <lan nic> ifconfig.me`) egresses with the VPN address. Enable again with the zone deleted by hand (`uci delete firewall.travo_vpn_lan; uci delete firewall.travo_vpn; uci commit firewall; reload_config`): the transaction restores only the zone, wg0 keeps its handshake, LAN egress returns. Repeat a first enable without confirming: the watchdog restores both `network` and `firewall` (no `travo_vpn`). Record pass or fail in SPIKES.md with addresses redacted.

**WireGuard rollback (#108).** Run `scripts/test-wireguard-rollback.sh` for the real watchdog in a disposable ARM64 OpenWrt container. It uses generated keys and documentation addresses and checks the live endpoint after each restore. For release acceptance on AXT1800, take a fresh backup and have an Ethernet or console fallback ready. Start with an enabled tunnel using a controlled literal-IP endpoint. Apply a change to a second endpoint and verify it is live before triggering each restore path: explicit rollback, failed probe, confirmation timeout and startup recovery after killing the watchdog before it claims restore. Require the old endpoint in `wg show wg0 endpoints` and a final RolledBack result. Repeat with an absent or disabled baseline and require no live `wg0` link after rollback. Record outcomes and elapsed times in SPIKES.md with endpoint addresses redacted.

**Captive portal (#129).** Use a real hotel network, or the local portal simulator below. Detection: on the portal uplink, the Dashboard shows the "Hotel WiFi login" card with Internet "Captive portal" within one probe (≤3 s), and "Open hotel login" opens the simulator's `/login` page in a new tab on a LAN client. After "logging in" (stop the simulator's redirect, or let it answer 204), the card disappears within one dashboard refresh. Without a kernel default route the card is absent and Internet reads Offline immediately (no 3 s wait). Record pass or fail in SPIKES.md.

**Captive DNS bypass (#130).** Same setup, with AdGuard (or any `noresolv=1` forwarder) as the base so the portal name does not resolve through it. Record `uci export dhcp` before. Press "Use hotel DNS for 5 min": `uci export dhcp` shows `list server '10.66.0.1'` (the hotel DNS from DHCP), `rebind_protection '0'`, `noresolv '0'`; `nslookup portal.hotel.test 192.168.1.1` from a LAN client answers `10.66.0.1`; the card shows the countdown. Press "Restore DNS now": `uci export dhcp` matches the recorded base byte for byte and the card leaves (unless still captive). Enable again and wait 5 minutes: the base returns without a click within 15 s of the deadline. Enable, restart the daemon (`/etc/init.d/travo-greenfield restart`), and verify the countdown reappears at about 5:00 and restores. `ls /etc/travo-greenfield-guards/` has no `dns-layer-in-progress` after each step.

**Captive DHCP renew (#131).** With the uplink on `wwan` (STA) behind a portal (or the simulator on a laptop AP), the card offers "Renew hotel connection"; on Ethernet `wan` or when online it does not. Press it: `logread | grep -i udhcpc` shows a renew on the STA device, no `ifdown`/`wifi`, the kernel default route via the STA stays or returns within 10 s, the UI says "Lease renewed", and `ls /etc/travo-greenfield-guards/` has no `captive-dhcp-renew-in-progress`. The netifd call itself is covered by `internal/captive/hardware_test.go` (`TestHWRenewWWANProvesRoute`, run on the router per "Hardware layer").

*Local portal simulator.* A Linux laptop with two interfaces plays the hotel: its uplink NIC has internet, its portal NIC (example `eth1`, address `10.66.0.1/24`) is cabled to the AXT1800 `wan` port. On the laptop, as root: `dnsmasq --no-daemon --interface=eth1 --bind-interfaces --dhcp-range=10.66.0.50,10.66.0.99,1h --dhcp-option=6,10.66.0.1 --address=/#/10.66.0.1` (every name resolves to the portal, like an unauthenticated hotel resolver; the hotel DNS offered by DHCP is `10.66.0.1`) and `python3 -c 'import http.server as h;exec("class R(h.BaseHTTPRequestHandler):\n def do_GET(s):\n  if s.path==\"/login\": s.send_response(200);s.end_headers();s.wfile.write(b\"<h1>Hotel login</h1>\")\n  else: s.send_response(302);s.send_header(\"Location\",\"http://portal.hotel.test/login\");s.end_headers()");h.HTTPServer(("10.66.0.1",80),R).serve_forever()'`. Do not enable forwarding: the portal never lets the router online. Set the router's uplink to `wan` (Ethernet) for the run. Stop both processes afterwards; nothing on the router is changed by the simulator.

**AdGuard Home install and loopback migration (#132).** From Ethernet with a fresh sysupgrade backup. GET-only first: record `GET /api/v1/adguard` and `netstat -lntup | grep AdGuard` (expect `:::3000`, `:::5353` on the old-Travo install). (a) Migration: start the daemon with the old-Travo config (`http.address: 0.0.0.0:3000`). Within one minute `GET /api/v1/adguard` reports `loopback:true, running:true, busy:false`; `netstat` shows `127.0.0.1:3000` and `127.0.0.1:5353` only; `wget -qO- http://192.168.1.1:3000/` from a LAN client fails; `nslookup -port=5353 example.com 127.0.0.1` on the router resolves; `diff` of the yaml against the backup changes only `http.address` and `dns.bind_hosts`; `/etc/travo-greenfield/adguardhome.yaml.old` and `/etc/travo-greenfield-guards/adguard-config-in-progress` are absent. (b) Restore: with a yaml whose `http.address` port is taken by another listener, run the migration and verify the old file is back and AGH answers again. (c) Fresh install: `apk del adguardhome`, remove `/etc/adguardhome/adguardhome.yaml` and `/etc/travo-greenfield/adguard-install-attempted`, restart the daemon with the uplink online. AGH must never listen on `0.0.0.0:3000` (poll `netstat` every second during the install); afterwards the yaml equals `internal/adguard/seed.yaml`, AGH runs with the hagezi filter list and answers on `127.0.0.1:3000`, and no `adguard-install-in-progress` guard remains. Record versions, times and pass/fail in SPIKES.md.

**AdGuard default DNS and fail-open (#133).** From Ethernet with a fresh backup, AGH migrated to loopback (#132). (a) Adopt: on old Travo's forwarding (`list server '127.0.0.1#5353'`, `noresolv='1'`) with no `/etc/travo-greenfield/dns-layers.json`, start the daemon: within 15 s the record exists with layer `adguard` and `uci show dhcp` is unchanged; `GET /api/v1/adguard` reports `default_dns:true`. (b) Fail-open: `/etc/init.d/adguardhome stop`; within about 60 s (3 probes, 15 s apart) `uci show dhcp` has no `server` and no `noresolv`, `nslookup <fresh name>.example.com 192.168.1.1` from a LAN client resolves through the uplink, and the API reports `default_dns:false` with `fail_open_since` set. (c) Hold-down: start AGH again; `default_dns` stays false for 10 minutes of passing probes, then the layer returns. Repeat (b) and re-enable with `POST /api/v1/adguard/dns {"enabled":true}` instead: immediate. (d) User off: `POST /api/v1/adguard/service {"enabled":false}` removes the layer before AGH stops (no REFUSED window: run `nslookup` in a loop during the call), and the probe never re-adds it. (e) No uplink (`ifdown wwan` from Ethernet, then `ifup wwan`): no fail-open. Record times in SPIKES.md.

**AdGuard gated proxy (#134).** From a LAN client with AGH on `127.0.0.1:3000`: `curl -si http://192.168.1.1:3001/` without a session is 401; after logging in to Travo in a browser, `http://192.168.1.1:3001/` shows the AGH dashboard, and changing a setting (e.g. toggle protection) succeeds. `curl -si -X POST -H 'Origin: http://evil.example' -b tg_session=<cookie> http://192.168.1.1:3001/control/protection` is 403. From the uplink side, port 3001 is not reachable. With AGH stopped the proxy answers 502 naming `adguardhome`. Record pass or fail in SPIKES.md.

**VPN kill switch (#89).** From Ethernet with the lock held and `uci export firewall` saved. Enable the kill switch in the VPN page and confirm: `uci show firewall | grep travo` lists `travo_vpn`, `travo_vpn_lan` and `travo_killswitch_wan`, the user's `@forwarding` lan → wan is unchanged, and `nft list chain inet fw4 forward_lan` shows the REJECT rule before `jump accept_to_wan`. `ifdown wg0`: the LAN client has no internet (`curl --max-time 8` fails) while the router still answers on :80. `ifup wg0`: LAN egress returns via the tunnel. Disable the tunnel from the VPN page: LAN stays blocked. Disable the kill switch and confirm: LAN egresses via the uplink, `travo_killswitch_*` is gone, `travo_vpn` remains. Repeat enable without confirming and verify the watchdog restores the firewall. Record pass or fail in SPIKES.md with addresses redacted.

**VPN split tunnel (#90).** From Ethernet with the lock held and `uci export network` saved, tunnel connected. In the VPN page set one /32 for an echo service's address (for example the address `ifconfig.me` resolves to) and confirm: `uci show network | grep travo_split` lists it plus a /32 per profile resolver, peers show `route_allowed_ips='0'`, `ip -4 route show dev wg0` lists those routes, and the kernel default uses the uplink. **VPN DNS layer (#88).** From Ethernet with a profile whose `[Interface]` has `DNS =` lines. Before enabling, record `uci show dhcp | grep -E 'server|noresolv'`. ## Web

`pnpm -C web check`: Biome, svelte-check, Vitest (pure logic and server-rendered components), build, UI size budget. Visual and keyboard behaviour (theme, drawer, focus) is checked in headless Chrome at 390 px and 1280 px before a UI PR; attach screenshots to the PR.

`mise run screenshots` writes PNGs for UI PRs to `web/screenshots/`; `web/scripts/cdp.mjs` is the shared headless-Chrome helper for browser checks.

Saved uplinks (#72): build, then run `scripts/with-mock.sh -- node web/scripts/e2e-wifi-profiles.mjs`. It saves, reorders, selects (stubbed transaction) and forgets at 390 px in light and dark and writes ignored screenshots to `web/screenshots/wifi-profiles/`. Set `CDP_PORT` to run beside another headless Chrome.

Component migration checks: build, then run `scripts/with-mock.sh -- node web/scripts/e2e-components.mjs`. These check keyboard/focus, form validation, confirmations and transaction controls against mock/HTTP seams. See [the migration inventory](testing/shadcn-migration.md); no hardware is required.
