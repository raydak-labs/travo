# Testing

Unit-green does not mean it works. Several real bugs shipped green because a fixture invented a field the device never emits.

## Layers

1. **Unit** with fixtures: verbatim captured device payloads, each with provenance (device, firmware version, date) in `testdata/`. Never hand-write a payload field.
2. **Container integration**: the official `openwrt/rootfs` image (25.12; 24.10 for the opkg adapter) with real `uci`, `ubus`, `rpcd`. Catches mocks that diverge from real semantics.
3. **Hardware playbook** per release on a real device. Some behaviour is provable only there: wireless apply/confirm, lockout, DNS composition with VPN + captive + AdGuard, sysupgrade survival, AdGuard reinstall, watchdog restore.

## Rules

- Mocks reproduce real semantics: `uci set` upserts (a mock that errors on an existing section is a false failure); a mock that ignores the device name is a false pass.
- A constant asserted against itself proves nothing. Check timing budgets against measured latency.
- Test the fail-closed direction explicitly: a broken AP reads DOWN; an unknown caller is refused.
- Property tests for the DNS layer stack (any push/pop order restores base).
- Transaction unit tests stub host-wide `sync` so disk load cannot consume the restore timeout; container and hardware tests use real `sync`.
- Table-driven tests for caller classification using real payload shapes.
- No destructive probes (e.g. reboot POST) against an unknown build: GET-only reachability first.
- Verify the running binary is the one under test (path + version) before measuring.

## Contract tests

Scripts parse; guard paths under `/etc/travo-greenfield-guards/`; every route is in the spec; auth covers every route (walk the live route table); strict-PUT coverage; spec field names match models; no feature writes UCI outside the transaction module; generated files (OpenAPI, TS client) have no diff.

## Mock mode

`--mock` runs the whole daemon against the mock `Device`, scripted from fixtures. Frontend development needs no device.

## Running the container layer

`mise run test:integration` cross-compiles the `integration`-tagged tests and runs them against real `uci`, `apk` (`openwrt/rootfs:aarch64_generic-25.12.6`) and `opkg` (`openwrt/rootfs:x86-64-24.10.8`, amd64: no arm64 24.10 manifest exists) (needs Docker). A second step boots the image with `/sbin/init` (procd as PID 1, real ubusd/rpcd/netifd) for tests that need procd. `mise run test:package` builds the release tarball and, in a booted `aarch64_generic-25.12.6` container, runs `install.sh` (refusals, install, health on `:80`, LuCI moved, other listeners intact), restarts the container (boot link), then `--uninstall` and `--uninstall --purge`. It also runs the signature cases (ADR 0007) with throwaway minisign keys from the host (`minisign` from `mise.toml`): no `.sig` refuses (`--insecure` hint); `--insecure` installs and writes no key; a valid `.sig` installs and stores the tarball key; a tarball with another key refuses ("differs from the installed key") and installs with `--rotate-key`; a `.sig` from another key and a tampered `checksums.txt` both refuse with "signature check failed". The real release key is never used. `mise run test:port80` checks the dual-stack port swap, exact LuCI listener restoration, rollback and retry after interruption, and refusal when another process owns port 80. Both packaging suites run on arm64 and are outside `mise run check`. A booted container counts as up only at procd's `- init complete -`: its S98sysntpd waits ~30s on a `ubus call network.interface dump` that container netifd never answers, so S99travo-greenfield starts ~35s after boot (a dnsmasq-running check made the post-reboot health wait flaky). CI runs `integration (amd64)` (`mise run test:integration amd64`) on every PR and push to main that touches non-docs files. `integration (arm64)` (native arm runner: `mise run test:integration arm64`, then `test:package`, `test:port80` and `test:update`) runs only on release-please PRs for now, because it is the slowest leg (see the TODO in `.github/workflows/ci.yml`); run `mise run test:package` locally when a change touches packaging. No arg runs both arches locally. Container fixtures prove format and quoting only, never wireless or netifd behaviour; mark them as such in `testdata/PROVENANCE.md`.

## Hardware layer

Test router: GL-AXT1800, OpenWrt 25.12.6, `ssh root@192.168.1.1` (key auth) when the operator has it on LAN. Start from a clean OpenWrt baseline for the release playbook. Before any live test, take a `sysupgrade -b` backup to the operator's machine and keep it outside the repo. Pause competing configuration writers and restore any paused processes afterwards. Diff `/etc/config/*` and the crontab against the backup after rollback tests. Never `wifi` / `wifi up/down/reload`. GET-only first.

`hardware`-tagged tests (`internal/txn/hardware_test.go`, `internal/dnslayer/hardware_test.go`, `internal/captive/hardware_test.go`) run ON the router from Ethernet: cross-compile with `GOOS=linux GOARCH=arm64 go test -tags hardware -c`, copy with `scp -O`, run with `-test.timeout` (no `timeout` in BusyBox). They change live wireless/DNS state and rely on the watchdog/stack to restore it; take a sysupgrade backup first and pause competing configuration writers. The reboot test needs a temporary boot hook that calls `Recover`; remove it after. Results of the first run: `testdata/device/axt1800-25.12.6/SPIKES.md`.

**AdGuard Home on port 53 (#186, ADR 0021; joint session, laptop on Ethernet + phone on WiFi).** A failed step is a LAN-wide DNS outage: keep the console or SSH via IP open, `uci export > /tmp/agh-topo-before.uci` and copy `/etc/adguardhome/adguardhome.yaml` aside first. Precondition: AGH running, default DNS on, guest AP configured. (1) Services → DNS setup → Expert → "Move AdGuard Home to port 53", confirm the danger dialog. While the toast counts down: `netstat -lnup | grep ':53 \|:5354 '` shows AGH on `127.0.0.1:53`, `192.168.1.1:53`, `192.168.2.1:53` and dnsmasq on `:5354`; `uci get dhcp.@dnsmasq[0].port` = 5354, `uci get dhcp.lan.dhcp_option` contains `6,192.168.1.1`; `nslookup travo-$RANDOM.example.com 192.168.1.1` answers NXDOMAIN; on the router `nslookup openwrt.org 127.0.0.1` answers. Let the window run out without confirming: within window + 30 s the yaml equals the copy (`cmp`), dnsmasq is back on :53, AGH on `127.0.0.1:5353`, `uci get travo-greenfield.main.adguard_topology` fails, the phone resolves a fresh name, no `adguard-topology-in-progress` guard is left. (2) Switch again and keep the change. Renew DHCP on laptop and phone: the DNS server is the router address; AGH's query log (via port 3001) shows the laptop and phone addresses, not 127.0.0.1. A `*.lan` name of a DHCP client and a local DNS name resolve; with the VPN tunnel on, `vpn/dns/verify` passes and a DNS leak test shows only the tunnel resolvers; Tailscale MagicDNS names resolve. A guest client resolves via `192.168.2.1`. Stop, default-DNS toggle and DoH save are refused with `adguard_expert_topology`. (3) Fail-open: `kill -STOP $(pidof AdGuardHome)`; within ~60 s `logread -e travo-greenfield` shows "expert topology failed open", dnsmasq answers on :53, the Services banner shows "AdGuard Home stopped answering", the phone resolves. `kill -CONT` it; AGH is back on `127.0.0.1:5353` and the default DNS layer returns after the 10 min hold-down; expert stays off. (4) Switch to expert, then "Back to the default setup" and keep: config and UCI equal the step-0 copies except the AdGuard UI edits made meanwhile. Restore the copies if anything differs and record pass/fail in SPIKES.md.
