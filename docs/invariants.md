# Invariants

MUST rules. Each came from a real incident or device finding (see [device-facts.md](device-facts.md)). A change that breaks one needs an ADR first. `[HW]` = proven on hardware only.

Paths: guards in `/etc/travo-greenfield-guards/`, state in `/etc/travo-greenfield/`, settings in UCI `/etc/config/travo-greenfield`. Guards never live in `/etc/travo-greenfield/`.

## 1. Live-state safety

- Any automated action that changes LIVE state (connectivity-affecting commit, apply, firewall, routes, radios, package ops, sysupgrade, factory reset, restore) writes a guard file FIRST and removes it ONLY after full success.
- Guard present → the feature SKIPS. Stale guards are reported at startup (a stuck guard is silent feature death).
- Manual redeploy/reinstall is the explicit retry path; it clears guards by NAME, never by glob.
- Guard write fails → abort the operation. Never degrade to unguarded.
- A guard check and the guard write are ONE step (`guard.Dir.AcquireExclusive`: a process-wide lock around scan + create; the file is created by hard link, so a same-name create fails also across processes; directory fsync). Never Stale()-then-Acquire with I/O between. An operation that refuses others' guards passes its conflict policy to that call (`guard.RefuseAny`, `guard.RefuseTerminal`, its own); a refusal writes nothing. Automated actions that run through a transaction (WiFi schedule, slide switch) pass `txn.RefuseAnyGuard(ctx)` so `Begin` refuses any held guard in that step (`skipped_guard`).
- Confirmed reboot writes `reboot-in-progress` and its boot record before scheduling. After scheduling succeeds, keep both until the next daemon start proves a different kernel boot id; setup or scheduling failure releases the guard, and a same-boot guard becomes retryable only after `reboot.Grace`.
- Factory-reset guards are never removed (interruption must stay visible). The firmware-upgrade guard is removed only at daemon start when the boot id AND the firmware revision both differ from the ones recorded in it (the flash finished); an interrupted flash or anything unreadable keeps it ([adr/0030](adr/0030-firmware-guard-completion.md)).
- Every shell-out has an explicit timeout tier. Exceptions: terminal ops (reboot, poweroff, sysupgrade, firstboot) and long-lived listeners (stopped by lifecycle signal, not timeout).
- Every background worker is registered in one lifecycle. SIGTERM stops all; no UCI commit after stop.
- Handler panic → 500; the process survives.
- Wireless changes: snapshot → commit/apply → rollback watchdog → explicit user confirm, only after proof the device is still reachable. The backend NEVER self-confirms, except for the automated actions in the list below. Adding to the list needs an ADR naming the trigger, the probe that must pass before the confirm, and how lockout is refused.
- The confirm window is the transaction manager's (60 s) for every change except the LAN address change (180 s, confirmed from the new address, [ADR 0028](adr/0028-lan-address-change.md)); a per-change window may only be longer.
- Automated self-confirm exceptions (each confirms only after its probe passes, never on a timer alone):
  1. WiFi schedule: a saved schedule rule toggles an AP's `disabled` flag through the AP transaction and confirms after the AP probe passes; lockout-risky rules need the acknowledgement saved with the rule ([adr/0027](adr/0027-wifi-schedule.md)).
  2. Slide switch: a hotplug `BTN_<n>` event runs the bound action (VPN tunnel or guest AP) through its own transaction and confirms after the feature's probe passes (fresh WireGuard handshake or uplink default route; guest AP probe); it runs as an unknown caller without acknowledgement, so lockout fails closed ([adr/0029](adr/0029-slide-switch-self-confirm.md)).
- Apply paths write UCI only. Never `wifi`, `wifi up/down/reload`, in any path. Auto-reconnect uses `ifup wwan` only. It is capped at 5 attempts, guarded, persists its counter, writes no UCI and never switches saved uplinks ([ADR 0014](adr/0014-capped-uplink-reconnect.md)).
- Manual uplink restart runs `ifup <name>` for `wan`, `wwan`, `usbtether` only, never `lan`/guest and never a stop. It writes no UCI, holds `interface-restart-in-progress` until the interface reports up with a fresh uptime or 30 s pass, refuses while a transaction or any other guard is held, and keeps the guard if `ifup` fails (the next explicit restart clears it). `wwan` drops every AP on the STA's radio (device-facts §2), so it is lockout-checked (§2) when one shares it.

## 2. Lockout safety

- A mutation that would leave the caller with NO enabled AP while the caller is on WiFi → 409 `wifi_lockout_risk` BEFORE any write. Override only with `acknowledge_lockout: true`.
- Caller classes: ethernet / wifi-ap / wifi-client / unknown. Unknown FAILS CLOSED (refuse unless acknowledged).
- Affected mutations: mode→client, radio disable, role change to none/sta, AP disable, guest disable, and a join that moves an AP to the other radio. A moved AP does NOT count as the caller's AP staying enabled (its clients drop during the move): a WiFi caller on it is refused unless acknowledged or another non-guest AP stays up.
- Must NOT block: SSID change, key change, disabling one radio while another AP is up, disabling guest while another AP is up, anything over Ethernet.
- Verify on a device, not only in unit tests.

## 3. Auth and access

- Admin login = root password validated via rpcd `session.login`. Mock mode: local check.
- Cookie session (HttpOnly, SameSite=Strict) + CSRF header. Live push is SSE on the same cookie. No tokens in query strings.
- API tokens (ADR 0008): bearer header only, never in a query string; stored as sha256 only; `read` scope never writes and never reads secrets; no token reaches token management, password, logout or session routes; tokens survive password change and die only by explicit revoke.
- Session validity uses the MONOTONIC clock; the API returns only a relative `expires_in`; clients never compare server timestamps with their clock. Lifetime 24 h.
- Protected routes default-DENY. The public list is a small explicit set (spec, health, login, first-run, time-sync). Adding a public route is a security change.
- Routing is case-sensitive: `/API/v1/...` → 404.
- Password change → revoke ALL sessions (persisted epoch file), return a replacement session. Min length 8. Logout/revocation survives restart; only hashes stored, never tokens.
- No fallback signing secret; entropy failure is fatal.
- Rate-limit login and pre-login endpoints; periodically sweep per-IP state.
- Optional IP allowlist (CIDR); health/login/time-sync bypass it.
- HTTPS (self-signed, [adr/0016](adr/0016-self-signed-https.md)) serves the SAME handler as HTTP: no route, check or exemption may depend on the scheme except the cookie's `Secure` flag. TLS never redirects or sets HSTS. A TLS listen failure is never fatal.
- Pre-login time-sync only while the router clock is implausible; sticky once plausible; bounded window; rate-limited. Authenticated callers unbounded.
- Root SSH keys: write only dropbear `authorized_keys`; append exactly one validated line; reject `\n`/`\r`; strict key-type format; no options field (`command=`, `from=`); list/add/delete behind auth; add and delete are session-only (no API token: a key is a root shell); unparseable lines are kept verbatim and never deleted; not revoked by redeploy or password change.
- Tailscale is off after install: the install flow pins DNS off, then stops tailscaled and removes its boot link. `PUT /tailscale/running` switches it on (boot link, start) or off (stop, no boot link); off is not a logout, the state file keeps the node key.
- Tailscale: login, logout, settings (exit node, LAN advertisement, Tailscale SSH) and switching it on or off are session-only (joining a tailnet or Tailscale SSH is a root shell). The pending `auth_url` is a secret: API tokens get it empty in `GET /tailscale` and in the `tailscale` dashboard event.
- Admin reachable on `br-lan` only (wired + AP WiFi). Uplink zones and guest get no admin access. Enforced by firewall AND daemon source check (by `RemoteAddr`, never forwarded headers). No reverse proxy on loopback in front of the daemon: loopback is trusted. No default password, ever. The `Host` header must name the router (its lan IP, loopback, `localhost`, or an allowlisted name), else 421: DNS rebinding must not reach the API.

## 4. API contract

- REST JSON under `/api/v1`. Health `GET /api/health` public. OpenAPI 3.1 at `GET /api/openapi.json` (public), GENERATED from typed handlers, never hand-written; drift fails CI.
- Every operation has a unique id and summary. Every route is in the spec. No route outside the registration path.
- Whole-config PUT is STRICT: unknown field, null, trailing data → 400 naming the field. GET and PUT shapes are symmetric.
- Validate ranges/enums explicitly. Silent acceptance of a bad value is a defect.
- Errors: `{error, code?}`; stable `code` for client branching, never message text. Ack: `{status:"ok"}`. Empty collections encode `[]`/`{}`, never `null`.
- Missing optional package → 503 naming the package, not 500.
- Limits: body 64 MB, read timeout 5 min, write timeout 45 min (package streams), idle 60 s on every listener (HTTP, HTTPS, AdGuard proxy); the dashboard stream and the firmware upload set per-request deadlines through `http.ResponseController`, graceful shutdown ~20 s; HTTP drains BEFORE services and persistence close.
- Long ops stream (NDJSON-like). Live status via one shared push subscription, never per page.
- Dashboard stream sources run on every tick while any dashboard is open, so they stay cheap: no package-manager query, no fan-out that the data does not need (the clients source reads one station list per AP, every 10 s). A package status read with such costs gets its own slim reader (`internal/uplinkview`). The uplinks source also reads the kernel default route and, only while wwan is up, one `iwinfo info` on its STA for the signal.
- GET never mutates.

## 5. Persistence

- UCI is the source of truth for device config; no shadow state. Derived JSON in `/etc/travo-greenfield/`; crash-critical records in `/etc/travo-greenfield-guards/`.
- Flash is NAND overlayfs: per-sample/per-request writes FORBIDDEN; batch; rare event-driven writes may write through. Keep ~20 MB free.
- Atomic writes for every state file (temp + fsync + rename). A torn file fails closed, never reads as "empty".
- Degraded persistence must be visible in the UI: `/overlay` on tmpfs or mounted read-only raises the `persistence_degraded` alert; under 20 MB free raises `overlay_low` (`internal/alerts`, derived on read, pushed as the `alerts` event on the dashboard stream). `MemAvailable` (`ubus call system info` memory.available) under 15 MiB raises `memory_low` as a warning, under 8 MiB as danger; read through the Device port, nothing written.
- Backup/restore = config tarball; restore over `/` is guarded. Factory reset is guarded (`factory-reset-in-progress`, never removed by Travo; the wipe takes it with the overlay), refused while any other guard is held, requires the typed phrase `factory reset` and a browser session (no API token).
- Firmware upgrade is guarded (`firmware-upgrade-in-progress`, written before `sysupgrade` is scheduled with the boot id, firmware revision and image SHA-256 in its `detail`; Apply never removes it) and refused while any other guard is held. It flashes only the image it validated in this daemon run (sha256 match, `valid`, never forced), requires the typed phrase `upgrade firmware` and a browser session (no API token). Completion and the keep-list: [adr/0030](adr/0030-firmware-guard-completion.md); `install.sh` is the explicit retry path and clears that guard by name.
- Firmware upload: one at a time (409 `firmware_upload_busy`); the slot is taken before the body is read and held until the request ends; refused before the body is read unless RAM and `/tmp` hold the request plus 32 MiB.
- Firmware upgrade and factory reset scan and write their guard in one step (`AcquireExclusive`, refusing any other guard): a refusal writes no guard, and once written no other guarded operation of the daemon can start. Reboot still writes then scans and answers 409 `operation_in_progress`, so of two racing requests at least one refuses. Transactions (`txn.Begin`, `txn.Apply`) and package operations refuse while a firmware-upgrade, factory-reset, reboot or update guard is held ([adr/0005](adr/0005-transactions-and-watchdog.md)).
- No embedded KV store. Add one only with a retention rule for the data.
- Stats history ([adr/0026](adr/0026-stats-history.md)): never written per sample; flushed at most every 6 h and on graceful shutdown. A torn file or failed flush degrades persistence (visible, never overwritten) until the explicit reset. Day totals use the router's timezone (UTC when unreadable) and stored days are never rewritten. The data budget alert is derived on read and never writes.

## 6. UCI write discipline

- ONE process-global staged-changes area. Concurrent writers of one config destroy each other's staged sections.
- All writes go through one helper: lock the whole config set ONCE, revert the staged delta on failure, commit once.
- Locks are keyed on CONFIG NAME (not service; `firewall`/`network` are shared). Global sorted lock order. Locks are NOT reentrant; a helper called inside a transaction must not lock.
- Read paths are unlocked.
- Travo's cron jobs and button scripts never write UCI: they call the daemon through the hook socket ([adr/0024](adr/0024-daemon-hooks-for-cron-and-buttons.md)). `/etc/crontabs/root` is written only by `internal/crontab`, one marked block per feature; foreign lines are kept byte for byte.

## 7. Network and routing

- Candidate uplinks: `wan`, `wwan` (STA), `usbtether`. Omitting one yields a false "No Internet".
- "Internet reachable" is a real probe; carrier-only is a separate signal and must not be labelled "Internet". Route checks read the KERNEL table, never netifd status (see device-facts §1).
- Throughput charts select interfaces by NAME, never index 0 (`br-lan`).
- Tunnel state has exactly 5 JSON values: `disabled` / `configured` / `enabled_not_up` / `no_handshake` / `connected`. Evaluate these rules in order:
  1. An absent `network.wg0` WireGuard interface or `disabled=1` means `disabled` without a selected profile, otherwise `configured`. Absent, empty or `0` enables the interface; any other `disabled` value is a read failure.
  2. For an enabled interface, an absent netifd object or `up=false` means `enabled_not_up`. An absent netifd object is expected for a disabled interface and is not an error.
  3. If netifd is up but the WireGuard device vanished, the state is `enabled_not_up`.
  4. With netifd up, no handshake or newest handshake age ≥180 s means `no_handshake`; `0 ≤ age < 180 s` means `connected`. The 180 s threshold is WireGuard's `REJECT_AFTER_TIME` from `drivers/net/wireguard/messages.h`. Negative age is a read failure.
  - The newest handshake across peers is the evidence; `up:true` alone is not. The kernel default route and `allowed_ips` are not state inputs (split tunnel may omit a default route).
  - A read failure never becomes `disabled`, `enabled_not_up` or `no_handshake`: keep the last good observation with its original timestamp marked stale for at most 10 minutes, then return 503 `vpn_status_unavailable`.
  - An idle tunnel without keepalive can legitimately read `no_handshake` even when its configuration is otherwise healthy.
- WAN zone is resolved by name, never by index.
- Diagnostics (ping, traceroute, lookup) take a target that is an IP literal without zone or an RFC 1123 host name (≤253, no leading `-`, last label not numeric), checked in the service AND the adapter, and passed as one argv element, never through a shell. Each tool has a fixed argv and timeout tier; one run at a time; rate-limited per caller; output capped at 16 KiB.
- Wake-on-LAN takes only a 6-byte unicast MAC (checked in the service) and sends a 102-byte magic packet built in Go as an IPv4 UDP broadcast to port 9, bound to an up, non-uplink `br-*` bridge with an IPv4 prefix (lan, guest); the adapter re-checks bridge, broadcast and payload before opening a socket. No external tool, no package, no shell, no state change; one request at a time; rate-limited per caller.
- A new zone/forward/interface gets the full firewall surface (zone, masq, forwarding, input/output/forward policy) matching the `wan` pattern.
- Direct firewall commits outside the apply flow are named exceptions, each with guard + rollback.
- USB tethering ([ADR 0019](adr/0019-usb-tether-uplink.md)): a tether link is a `usb`-bus netdev with a phone driver, never matched by name. Enabling stages `network.usbtether` and its `wan` zone list entry in ONE `network` + `firewall` transaction the user confirms; it is not a direct-commit exception and nothing rebinds it from hotplug. Travo owns only that interface and that list entry.
- Wireless snapshot sets include firewall + dhcp.
- WAN settings: Travo edits only `network.wan` `proto` and that protocol's options, set-if-different, in ONE `network` transaction the user confirms. `device`, `wan6` and any other proto stay LuCI's (409 `wan_foreign_config`). The PPPoE password goes through `uci batch` on stdin (never argv), is never logged and never returned. A static subnet overlapping another configured interface prefix is refused before any write (409 `wan_overlaps_lan`). The probe reads the kernel table only and needs two consecutive readings after a settle; when wan was the active uplink only a route via it counts. Admin is lan-only (§3), so a wan change cannot strand the caller; the confirm still applies. Behaviour: [#240](https://github.com/blackdark-org/travo-greenfield/issues/240).
- LAN address ([ADR 0028](adr/0028-lan-address-change.md)): Travo edits only `network.lan` `ipaddr` of a static single-address lan, in ONE `network` transaction with a 180 s window (a window shorter than the manager's is refused), confirmed from the new address. Refused before any write: a subnet overlapping another interface, a DHCP pool outside the new subnet (never shifted), dhcp hosts/domains or redirects outside it or equal to the router address. The trust set (source check and `Host` allowlist, §3) is refreshed when the change is armed. The pending pointer is memory-only; a daemon restart rolls the change back. Behaviour: [#244](https://github.com/blackdark-org/travo-greenfield/issues/244).
- Port forwards: Travo creates and deletes only `firewall` `redirect` sections named `travo_fwd_<n>` (max 32); every other redirect is read-only. Each change is ONE `firewall` transaction the user confirms. A forward to the router itself MUST be refused (target must be a lan host inside the committed prefix, never the router's lan address), so no forward exposes the admin UI, LuCI or SSH to the uplink side; no acknowledgement overrides this. External ports 22/80/443 forwarded to a lan host are allowed without acknowledgement: wan input stays REJECT and admin is lan-only (§3), so such a forward shadows no router service. An enabled wan DNAT redirect overlapping on protocol and external port is refused before any write (409 `port_forward_in_use`). Behaviour: [#238](https://github.com/blackdark-org/travo-greenfield/issues/238).
- IPv6: Travo edits only `network.wan6` `disabled`, its own `network.wwan6` and `dhcp.lan` `ra`/`dhcpv6`, in one `network` + `dhcp` transaction the user confirms; the probe proves the kernel IPv4 default route is unchanged. Relay mode or foreign shapes are refused (409 `ipv6_foreign_config`). Enabling while `network.wg0` is enabled is refused (409 `ipv6_vpn_leak`; the tunnel is IPv4-only, §11); turning IPv6 off is always allowed. Behaviour: [#245](https://github.com/blackdark-org/travo-greenfield/issues/245).
- Dynamic DNS: the optional `ddns-scripts` package (§13, guarded install `ddns-install-in-progress`, 21 MiB free). Travo owns only the section `ddns.travo` (a non-`service` section on that name is refused, 409 `ddns_foreign_config`); the package's sample sections and other services are never edited. Writes go through `txn.Apply`. The token goes through `uci batch` on stdin and never appears in argv, logs, errors or a response. Behaviour: [#245](https://github.com/blackdark-org/travo-greenfield/issues/245).

## 8. DNS layering

dnsmasq is the single DNS authority for upstream choice; in expert mode AGH owns :53 and forwards only to dnsmasq ([adr/0021](adr/0021-adguard-expert-topology.md)). Features that change DNS push/pop a layer on ONE ordered stack.

- Layers: `captive`, `vpn`, `adguard`, `tailscale`. Base state is captured before the first layer. No per-feature snapshot of the same options (`server`, `noresolv`, rebind protection, WAN DNS fields).
- Enable is idempotent. Disabling a non-top layer removes only its own entry. Last layer out restores base and deletes the record.
- Restore never reports success while a bypass could still be in force. Missing/corrupt record → refuse + keep guard (retry).
- Status reads never mutate DNS. Only an explicit POST or a scheduler with its own guard mutates.
- VPN self-heal on status read only for terminal "disabled"; "enabled-not-up" needs debounce (N readings over T seconds). A broken probe is not a broken tunnel.
- The `vpn` layer is owned by a reconciler (every 15 s, `internal/vpndns`), never by the tunnel transaction. It pushes the resolvers `wg0` was applied with (`network.wg0.travo_dns`, recorded by Enable; selecting a profile changes nothing until it is applied; [adr/0033](adr/0033-vpn-resolvers-recorded-on-wg0.md)) with `noresolv=1`, only on `connected` and only while no transaction awaits confirmation. It reads them under the `network` write lock and pushes only when no transaction began or held its guard from that read until the push; the tunnel state is read last. It pops on `disabled`/`configured`, or when the applied profile has no resolvers, also during a pending transaction. `enabled_not_up`, `no_handshake`, stale or unreadable inputs change nothing, except that unreadable resolvers do not stop the pop of a tunnel that is off. A stack change that kept its guard stops the reconciler until the explicit retry.
- DNS verify (`POST /api/v1/vpn/dns/verify`) checks, in order: no unfinished layer change, the `vpn` layer active and on top, dnsmasq's live `server` list equals the tunnel resolvers with `noresolv=1`, then a fresh random label resolves through `127.0.0.1:53`. NXDOMAIN counts as success; timeout or SERVFAIL is `lookup_failed`.
- The `tailscale` layer is additive (`server=/<MagicDNSSuffix>/100.100.100.100`, never `noresolv`) and owned by a reconciler (every 15 s, `internal/tailscale`): push while `Running` with MagicDNS on, pop when absent, logged out or stopped; transient or unreadable states change nothing ([adr/0017](adr/0017-tailscale.md)).
- Captive bypass is the `captive` layer: the active uplink's resolvers with rebind protection off. It never edits WAN DNS fields or the AdGuard upstream, so the stack's base is the only backup; never record the dnsmasq server list outside the stack. Auto-restore after 5 min (monotonic, memory-only deadline; a daemon restart re-arms a full 5 min, see [adr/0010](adr/0010-dns-layer-stack.md)).
- AdGuard: liveness probe resolves a fresh uncached name via `127.0.0.1:5353`. After M failures the `adguard` layer is popped (fail OPEN), a loud banner shows, and it does not re-enable until the user confirms or a probe passed for a hold-down period.
- AdGuard: forwarding written outside the stack (old Travo's base) is adopted as the `adguard` layer before any pop; turning AGH off pops the layer before stopping it.
- AdGuard offline bundle ([adr/0020](adr/0020-offline-adguard-bundle.md)): a local package is installed ONLY when its SHA-256 equals the pin stamped into the signed binary; a mismatch is never installed and falls back to the online path. The bundle lives in RAM (`/tmp/travo-greenfield-bundle/`), never on flash.
- AdGuard memory caps ([adr/0006](adr/0006-adguard-package-and-topology.md#memory-caps)): Travo keeps `adguardhome.config.memlimit` ≤ 64 MiB on every reconcile. The YAML caps (`querylog`, `statistics`, `dns.cache_size`) apply ONCE per router (marker `adguard-caps-applied`); afterwards Travo never touches those keys, so values the user raises stay, and smaller values always stay. Travo restarts AGH at most once per reconcile, only when something changed, and never when the user stopped it.
- AdGuard binds loopback, plus the lan/guest addresses on port 53 in expert mode; the admin UI stays loopback. It has no accounts and is reached through the Travo-gated proxy. No first-run wizard is ever exposed on the LAN.
- AdGuard expert topology ([adr/0021](adr/0021-adguard-expert-topology.md)): AGH answers on `127.0.0.1:53` and the served pool addresses, `upstream_dns` is only dnsmasq on `127.0.0.1:5354`, no `fallback_dns`; the `adguard` layer is never active in expert mode (it would loop). A switch in either direction is ONE transaction over `dhcp` and `travo-greenfield.main.adguard_topology` with AGH's YAML kept under `adguard-topology-in-progress`; the probe resolves a fresh name on port 53 of every bound address before the user can confirm. Failure or no confirm restores both exactly. After M liveness failures the daemon reverts to default by itself (the one automatic DNS port change); the guard stays until every step passed. Stopping AGH, the default-DNS toggle, DoH changes, creating the guest network and changing the LAN address are refused in expert mode.
- DNS over HTTPS is AdGuard's `upstream_dns`, never a layer or a dnsmasq option ([adr/0010](adr/0010-dns-layer-stack.md#dns-over-https-is-adguards-upstream-not-a-layer-245)). A new upstream is written only after AGH's `test_upstream_dns` answered `OK` for it; a failed test changes nothing. Its outage is AdGuard's fail-open path above.
- Local DNS names are dhcp `domain` sections (`name`, `ip`), never options of the dnsmasq section the stack owns. Travo creates and deletes only `travo_dns_<n>` (max 64); other domain sections are listed read-only (409 `dns_name_foreign`). A name any domain section already answers is refused (409 `dns_name_exists`). They are hosts-file entries dnsmasq answers before forwarding, so they hold under every layer ([adr/0010](adr/0010-dns-layer-stack.md#local-dns-names-beside-the-stack-239)).

## 9. Multi-WAN failover (mwan3, IPv4 only)

- Source of truth is Travo's failover JSON, generated into `/etc/config/mwan3`. Generated sections are prefixed `travo_`, except interface sections keyed by netifd name (`wan`, `wwan`, `usbtether`): those are created or adopted (loud warning), Travo owns only `enabled`, `family` and the tracking options, and they are never deleted ([ADR 0018](adr/0018-mwan3-failover.md)).
- Ownership = PROVENANCE (`travo_fp` stamped over the owned values and still matching), never content. A non-namespaced section is NEVER deleted.
- Rules `travo_v4` (→ `travo_failover`, `last_resort default`) and `travo_v6` (→ `default`, main table) sit at the top of the rule list; stock catch-all rules stay but never match first.
- Operator-edited `travo_` section: overwrite Travo-owned options with a LOUD warning.
- Back up EVERY section a save may write; restore on failure.
- Staged apply: apply with rollback → verify every managed section and mwan3's runtime (every chosen uplink online with tracking active, mangle rules marking for the first uplink through `travo_failover`) → confirm. Not confirm-then-verify; a request through the main table is no proof.
- Failback hold-down 30 s; walk the priority list, first uplink past hold-down wins (not "keep current first").
- Liveness from mwan3track pings (`track_ip`, ADR 0018 tracking values): without a tracker mwan3 never marks a member online. `family: ipv4` explicit; no IPv6 policy until device-validated.
- Guard during the apply window. Mocks must match real UCI semantics (`set` = create-or-update).
- Failover and Tailscale are mutually exclusive until #279 ([ADR 0018](adr/0018-mwan3-failover.md) "Failover and Tailscale"): enabling failover while tailscaled runs or is boot-enabled is 409 `failover_tailscale_conflict`; installing or logging in Tailscale while failover is enabled is 409 `tailscale_failover_conflict`. Both checks run under the one mutex the two services share; a failed check is an error, never "absent".
- Disable removes mwan3's leftovers from `ip`/`ip6 mangle` through the `MangleCleaner` port: only `mwan3_*` chains and the rules jumping into them, in one nft transaction, re-read afterwards. Foreign chains and rules are NEVER touched; a foreign jump into a `mwan3_` chain refuses the cleanup. Sole exception, before mwan3 starts on Enable: an iptables-nft-incompatible `mangle` base chain is deleted only when it holds no rule and its policy is accept; otherwise Enable refuses (409 `failover_mangle_incompatible`; [ADR 0018](adr/0018-mwan3-failover.md) "Stale mangle base chains").
- Uplinks whose IPv4 prefixes overlap are refused (409 `failover_same_subnet`): the backup's tracking fails with the primary. A failed apply probe names its check.
- A fresh `mwan3` install is stopped and disabled at once (its stock catch-all rules must never run). mwan3 runs only while the settings say enabled and the committed config carries the stamped Travo rules; a reconciler (5 s) stops it otherwise and boot-enables it only after the user confirmed.

## 10. WiFi model

- Roles: uplink STA (`mode=sta`, bound to `wwan`, in `wan` zone), downlink AP(s) (shared SSID/key default), guest AP (own subnet 192.168.2.0/24, own zone; refuse subnet overlap).
- Max ONE enabled STA bound to `wwan`. Multiple saved upstreams = ordered priority list, one active.
- Saved uplinks never write UCI on save, reorder or forget; select is a Join on a copy of the stored credentials and never rewrites the list. A saved uplink is connected only when the managed STA has carrier and `iwinfo info` reports its SSID (and BSSID when pinned); a configured SSID alone never counts. Keys never appear in list responses, errors or logs.
- With ≥2 radios, STA and AP go on DIFFERENT radios. Same-radio is an opt-in escape hatch, visible in health. Refuse STA enable on a radio carrying an enabled AP (409) unless single-radio/opt-in.
- Radio pick is deterministic (sorted by name, prefer no-AP). "Uplink radio" = radio of ANY enabled `mode=sta` iface.
- Layout reconcile happens BEFORE a single commit (stage STA, reconcile AP, commit once). Never commit AP+STA on one radio, even transiently.
- Health endpoint reports fragile layouts and invariant violations.
- Auto-reconnect has a failure counter so bad credentials are not retried forever; the counter is not a guard and is not cleared by redeploy.
- Band switching: persisted choice, guarded, a refused tick leaves no guard behind.
- Scan: one row per SSID, dual-band badge, per-AP disclosure. Scan must not commit the uplink onto an AP radio.
- Scan is read-only, one radio at a time, target = first interface ifname else radio name, concurrent requests join the in-flight scan.
- Wireless scan replies use `TierScan`, not `TierRead`.
- MAC clone/randomize; per-client MAC policies. The uplink policy is `macaddr` on the enabled `wwan` STA: absent = default, `random`, or a unicast MAC (clone stores the caller's neighbour-table MAC). The probe needs a new STA kernel link, carrier, the kernel default route via it and the effective MAC from `network.device status`: exact for custom, locally administered for random, universally administered for default (assumes a factory MAC is universally administered; verified per device in the playbook).
- Radio hardware status is CONFIGURED state, labelled as such.
- Post-apply probe proves each enabled AP/STA interface individually (see device-facts §2). Failure → rollback. "Could not read netifd" is distinct from "AP not up".
- AP edit stages SSID, key (via the key writer, never argv) and `disabled` for one AP in one transaction. Enabling an AP on a radio with an enabled STA → 409 `wifi_radio_in_use`, no write. Only disabling an enabled AP runs the lockout check, with the caller classified from live facts; any unreadable input classifies Unknown. The probe proves every AP expected enabled individually, the edited AP broadcasting the new SSID, and a disabled AP gone from `network.wireless status`.
- Guest AP: Travo-named sections (`wireless.guest`, `network.guest_dev`/`guest`, `dhcp.guest`, `firewall.guest`, `guest_wan`, `guest_dhcp`/`guest_dns`); the guest zone is input/forward REJECT and forwards to `wan` only, never `lan`. Staged set-if-different. A subnet overlap or a foreign `guest` section is refused before any write (409 `wifi_guest_subnet_overlap`, `wifi_guest_conflict`). The probe proves the main and guest APs individually.
- Join AP reconcile (dual radio): when no band-compatible radio is free but one carries enabled APs and another enabled radio can take them, the STA takes that radio and each AP on it moves (`device` only). Staged in one `Begin`: disable the enabled uplink STAs, move the APs, stage the STA, enable it last, so no staged state has an enabled AP and STA on one radio. Otherwise 409 `wifi_no_free_radio` with no write. A moved AP that does not come up rolls back STA and AP together.
- Join replaces one STA on wwan in place. It chooses the first band-compatible radio by name with no enabled AP, returns `wifi_no_free_radio` otherwise, and requires STA carrier and a kernel default route via that STA before arming confirmation. The STA kernel link index must be absent from the snapshot taken under the transaction lock before staging and remain stable across the carrier and route checks.

## 11. VPN

- WireGuard: profiles (import, list, activate, delete), enable/disable, kill switch, split tunnel, DNS verify, DNS leak test, speed test. Profiles in `/etc/travo-greenfield/`, tunnel in UCI `network.wg0`.
- Enable: stage the selected profile in the WireGuard transaction and prove a new handshake from one configured peer before confirmation. The transaction owns the wg0 interface (including the Travo option `travo_dns`, which netifd ignores) and wireguard_wg0 peer sections. Enable also stages the VPN zone `travo_vpn`, forwarding `travo_vpn_lan` and, when the Travo guest zone exists, forwarding `travo_vpn_guest` (guest → travo_vpn) (the kill switch's zone sections, `vpnkill.VPNZone`) in the SAME transaction (`network` + `firewall`, one snapshot, one confirm/restore): without a zone holding wg0, fw4 rejects LAN forwards into the tunnel and LAN clients lose internet while the router stays online (device-facts §1). Enabling an already matching tunnel whose zone is missing stages only the zone and does not restart wg0. Disable keeps the zone. The kill switch rules and DNS are separate operations.
- Disable must prove the wg0 link is absent and the kernel has a non-wg0 default route before confirmation. Recovery waits are bounded and never assume the uplink is `wan`.
- Split tunnel: the WireGuard transaction also owns `network.travo_split_<n>` route sections. With any present, every peer has `route_allowed_ips=0`, so only those IPv4 prefixes (≤32, no `0.0.0.0/0`, no IPv6) plus a `/32` per uncovered applied resolver (`travo_resolver=1`; user routes carry `0`) use the tunnel; the uplink keeps the default route. None present means a full tunnel. Re-enabling or re-applying a profile keeps the user routes; the resolver `/32`s follow the new resolvers. On an enabled tunnel the change restarts wg0, proves a new handshake, then proves the kernel default: via a non-wg0 uplink for split (bouncing the unique uplink if leaving full mode dropped it, device-facts §1), via wg0 for full. With the kill switch on, LAN clients reach only the split prefixes.
- Kill switch (`internal/vpnkill`) is firewall state in a `firewall` transaction the user confirms. Travo owns sections by NAME only: zone `travo_vpn`, forwarding `travo_vpn_lan`, one rule `travo_killswitch_<zone>` (src lan, REJECT, both families) per zone holding `wan`/`wan6`/`wwan`/`usbtether`, and for the Travo guest zone `travo_vpn_guest` plus `travo_killswitch_guest_<zone>`. Two owned rules on one name → 409 `vpn_killswitch_unsupported`. fw4 evaluates rules before zone forwardings, so the user's own lan → wan forwarding is never edited. A foreign section on an owned name, a missing `lan` zone or no uplink zone → 409 `vpn_killswitch_unsupported` before any write.
- Kill switch policy: enabling requires a fresh `connected` tunnel (409 `vpn_not_connected`) and its probe re-proves `connected` after the firewall reload. Once on it is STRICT: it holds across disconnects, `enabled_not_up`, a disabled tunnel and from boot; LAN clients have no internet until the tunnel is back or the user disables it. Disabling is always allowed and removes only the rules; the VPN zone stays. The router's own traffic is output, not forward, and is not blocked; the admin UI on br-lan stays reachable. Covered zones are `lan` and the Travo guest zone, detected only as section `firewall.guest` of type zone named `guest`; a user zone named `guest` elsewhere is never adopted, and no user-owned section is edited.
- Guest AP and VPN: the guest transaction (§10) stages the guest's VPN sections itself, set-if-different, in the same `firewall` snapshot (`travo_vpn_guest` when `travo_vpn` exists, `travo_killswitch_guest_<zone>` when the kill switch is on), because with the switch on `guest_wan` would otherwise leak guest traffic. A foreign section on one of those names → 409 `wifi_guest_conflict`; a kill switch that cannot cover the layout → 409 `vpn_killswitch_unsupported`; both before any write.
- Tailscale ([adr/0017](adr/0017-tailscale.md)): installed only on request (guarded, Internet probe, 46 MiB free). Every CLI write passes `--accept-dns=false` and Travo's full pref set. Login, logout and pref changes run under guard `tailscale-change-in-progress`, kept on failure and cleared by the user's next action. Its resolver is the `tailscale` DNS layer (§8). A newly selected exit node proves Internet within 20 s or the previous prefs are restored; an exit node while wg0 is enabled is refused (an unreadable tunnel fails closed). Travo owns firewall sections `travo_ts`, `travo_ts_lan` and, with LAN advertisement, `travo_ts_in`, in a confirmed `firewall` transaction; no guest forwarding; not an uplink zone for the kill switch.

## 12. Captive portal

- Detection: HTTP probe to a known 204 endpoint + redirect inspection. Only a 204 or a 200 with the known empty body means online; a 200 with a body or an http(s) redirect means captive (ADR 0022).
- Probe skipped when no default route (instant offline). Concurrent callers share one probe; cache ~2 s; a DNS change invalidates the cache. DNS-layer composition wires `dnslayer.Service.AfterApply` to the shared connectivity service's `Invalidate`, including when an apply fails after changing live DNS.
- DHCP renew is user-triggered only: `netifd renew` on wwan (never ifdown/ifup, never `wifi`), only while wwan carries the kernel default route and the probe is not online, under guard `captive-dhcp-renew-in-progress`; released when nothing was sent or a default route via wwan is proven within 10 s. A kept guard shows as `blocked`; the user's next explicit renew is its retry path (no automatic renew exists to skip).
- Auto-accept (ADR 0023) is user-triggered. Only step 0 may renew the wwan DHCP lease, only after its fetch failed, only when wwan is the active uplink and the renew guard is not kept, through the guarded `Renewer`; waits are bounded. It submits only fields the portal page supplied, never user data, verifies TLS, and changes no UCI or DNS. Every dialed address is checked: router-own addresses and the subnets of every non-uplink interface are refused, and the kernel must route the target out of the uplink.
- Warning card only when an action exists (login, DNS bypass active, connected-but-no-internet).

## 13. Package ops

- Package manager (apk on 25.x, opkg older) is detected at runtime behind a `PackageManager` port; never hardcoded. Package lists live in `/tmp`: refresh before install, best effort.
- Install writes init scripts, `/etc/config`, kernel modules → guarded, with a flash-space warning.
- One package operation at a time: every install, remove and list refresh (catalog, Tailscale, DDNS, AdGuard, failover, USB tethering, OpenWrt update check) holds the process-wide `pkgmgr.Exclusive` lock (waits, cancelled with the request), checks free flash only under it, and writes its guard with `guard.RefuseTerminal` (none during a firmware upgrade, factory reset, reboot or update). While a package-op guard is held, transactions refuse (409).
- Missing optional package → 503 naming it. A failed presence check is not "absent".
- Services catalog (#268): packages listed in the firmware image's `/rom/etc/apk/world` are never removed (`catalog_built_in`); install and remove share the guard `catalog-package-in-progress`, which the next explicit install or remove clears; an `apk del` that keeps a package another one needs exits 0, so remove re-reads presence and reports `catalog_in_use`.

## 14. Updates and releases

- Travo self-update: signed release (minisign public key embedded), download to `/tmp`, verify, keep previous as `.old`, atomic swap, procd restart, health check, automatic rollback on failure. Guarded. No background phone-home; on-demand and at most daily on page open. Release source configurable. Each release must stage with the previous release's stager ([ADR 0032](adr/0032-self-update-forward-compatibility.md)).
- After any upgrade verify the RUNNING exe path, not just file existence; restart, not start.
- Sysupgrade keep-list includes the init script, the boot link `/etc/rc.d/S99travo-greenfield`, binary, and UCI enable.
- Build stamps version and build time into the binary; build time is the time-plausibility floor. A missing stamp is a release defect.

## 15. Footprint and ops

- Single self-contained binary per arch, stripped, no runtime deps. Budget ~12.8 MB stripped; measure the delta before adding a dependency. Keep ≥20 MB flash headroom.
- Cron log level 9 (keep an operator's own setting) so per-minute job starts don't flood the error log.
- `install.sh` leaves `/www/travo-greenfield` holding exactly the UI files its manifest lists: asset names change every release, and leftovers make the self-updater refuse (its owned-files check, ADR 0007). It removes nothing outside that directory.
- Install requires an explicit `--password` or the first-run screen; the installer verifies the service answers on its configured port before reporting success, and refuses to move LuCI otherwise.
- Contract tests: scripts parse, guard paths under `/etc/travo-greenfield-guards/`, every route in the spec, auth covers every route (walk the live route table), strict PUT coverage, spec field names match models, no feature writes UCI outside the transaction module.
- Record a decision with evidence (firmware version + captured payload) for every device finding.

## 16. Clients

- The client list merges `/tmp/dhcp.leases`, the LAN-side kernel neighbour table (entries on a non-uplink interface device such as br-lan, so a hotel network on the LAN prefix never counts) and `hostapd.<ifname> get_clients` of every AP (never assoclist, device-facts §2). A neighbour on no AP's station list is `lan`, not "wired": br-lan carries both (device-facts §5). An unreadable lease file, neighbour table, station list or firewall drops out with `partial: true`; GET never mutates.
- Aliases live in `clients.json` in the state dir (ADR 0009): not device config, no transaction. An unreadable file, or one without an `aliases` object, fails closed and is never overwritten.
- Reservations are `dhcp` `host` sections through `txn.Apply` (dhcp cannot cut the caller off; the address applies on the next renewal). Travo creates `travo_host_<mac>`, edits or deletes a user section only when every MAC selector in it is that MAC (another MAC or a wildcard → 409 `reservation_shared`; removal keeps the other selectors), never touches the dnsmasq section the DNS layer stack owns, and commits nothing when the reservation is unchanged; an unchanged or already absent reservation still runs the idempotent `reload_config`, so a retry finishes a commit whose reload failed. The IP must be a host address of the COMMITTED lan prefix (staged network changes → 409 `uci_busy`) other than the router and not the `ip` of another host section (MAC-less ones included). Residual window: the network lock is not held, so a network commit between that read and the dhcp commit is not seen.
- Block is the firewall rule `travo_block_<mac>` in a `firewall` transaction the user confirms; it is forward only, so the blocked device still reaches the admin UI. Blocking the caller's own MAC → 409 `client_is_caller` before any write; an unreadable neighbour table fails closed. Only a section of exactly that shape counts as blocked; another section on the name → 409 `client_block_conflict`.
- DHCP server settings edit only `dhcp.lan` `start`, `limit`, `leasetime` and the off switch, set-if-different through `txn.Apply` after a UI confirm: a change applies to new leases and renewals, so it cannot cut the caller off at once. The pool must end inside the COMMITTED lan prefix (staged network → 409 `uci_busy`); lease `<n>m|h|d` ≥ 2m or `infinite`. Off sets `ignore '1'`; on clears `ignore` and a `dhcpv4 'disabled'`. A start or limit that is not a plain offset is LuCI's (409 `dhcp_foreign_config`). An unchanged request commits nothing but runs the idempotent reload. Turning the server off while the caller holds a lease is allowed; the UI warns.
- Kick is a named exception to the transaction rule: `hostapd.<ifname> del_client` (deauth, reason 5, no ban) changes no config and the station may rejoin at once. It runs under guard `client-kick-in-progress`, released on every return because hostapd's call is atomic; a guard left by a crash is cleared by the user's next kick (its retry path). The caller's own MAC → 409 `client_is_caller`; a MAC on no AP → 404 `client_not_associated`.

## Deliberate ceilings

Accept; do not "fix" silently.

- IPv6 failover deferred (IPv4 only). Needs a device matrix + decision record.
- Live throughput history ~10 min in memory; resets on restart. The 10 min bucket history survives restarts but loses up to 6 h on a crash or power cut (ADR 0026).
- Session registry is memory-only (cross-restart revocation via epoch only).
- Dashboard rate = 2 s sample, not an average.
- Config locks are held across blocking reload/apply; long holds queue all writers of that config.
- Push buttons and the reset button = detection only; slide switches run bound actions ([adr/0029](adr/0029-slide-switch-self-confirm.md)).
- Operator-owned external writers (cron/hotplug) outside the lock model.
- Guard exclusion is exact only inside the daemon process: the update worker and `install.sh` run as other processes, where only a same-name create is exclusive. `txn.Apply` holds no guard, so a terminal guard written after its check can meet an Apply's commit (one UCI config, no connectivity change).
- A package-op guard kept after a failed install blocks every transaction until that install is retried (its explicit retry path); the 409 names the guard.
- A client block stops NEW forwarded connections only: fw4 accepts established flows before the MAC rule (clients/fw4-print-block.txt) and the 25.12.6 image has no `conntrack` tool to flush them, so flows open before the block run until they close. The UI says so; disconnecting a WiFi client does not end them either.
- AdGuard sees all queries from 127.0.0.1 (no per-client stats) under the default topology; the opt-in expert topology ([adr/0021](adr/0021-adguard-expert-topology.md), #270) answers on port 53 and sees client addresses.
